TVIDefaultAudioDevice

Objective-C

@interface TVIDefaultAudioDevice : NSObject <TVIAudioDevice>

Swift

class TVIDefaultAudioDevice : NSObject, TVIAudioDevice

TVIDefaultAudioDevice allows you to record and playback audio when you are connected to a Room.

  • block

    @brief A block to configure the AVAudiosession.

    @discussion When you connect to a Room, the SDK executes this block. If CallKit is not in use (the connect options have no uuid), the SDK first activates the audio session. To reconfigure the session after connecting, for example to change the audio route, execute the block yourself. Please note that the getter of this property returns a wrapper block which internally executes the block you set. By default, the SDK returns a default wrapper block which executes kTVIDefaultAVAudioSessionConfigurationBlock internally.

    Avoid executing the block on the main thread. It configures AVAudioSession, and changing the category of an active session on the main thread can lead to UI unresponsiveness. Dispatch the call to a serial queue that your application owns, as shown below, so that successive reconfigurations are applied in order.

    @important The SDK invokes this block on its own serial background queue, not on the thread that called connectWithOptions:delegate:. Do not touch UIKit, read main-actor isolated state or assert NSThread.isMainThread from inside the block. The work is also asynchronous: it completes after connectWithOptions:delegate: has returned.

    The following example demonstrates changing the audio route from speaker to receiver:

    TVIDefaultAudioDevice *audioDevice = [TVIDefaultAudioDevice audioDevice];

    TwilioVideoSDK.audioDevice = audioDevice;

    // Created once, for example alongside the audio device. dispatch_queue_t audioSessionQueue = dispatch_queue_create(“com.example.audiosession”, DISPATCH_QUEUE_SERIAL);

    //…connect to a Room with audioDevice. By default the audio route will be configured to speaker.

    audioDevice.block = ^ { // We will execute kTVIDefaultAVAudioSessionConfigurationBlock first. kTVIDefaultAVAudioSessionConfigurationBlock();

       // Overwrite the audio route
   AVAudioSession *session = [AVAudioSession sharedInstance];
   NSError *error = nil;
   if (![session setMode:AVAudioSessionModeVoiceChat error:&error]) {
       NSLog(@"AVAudiosession setMode %@",error);
   }

   if (![session overrideOutputAudioPort:AVAudioSessionPortOverrideNone error:&error]) {
       NSLog(@"AVAudiosession overrideOutputAudioPort %@",error);
   }

    };

    dispatch_async(audioSessionQueue, ^{ audioDevice.block(); });

  • enabled

    @brief A boolean which enables playback and recording.

    @discussion By default, this property is NO. Connecting to a Room without CallKit enables it. Setting it to NO stops the underlying CoreAudio graph (if active) and prevents it from being started again. Setting it to YES allows the audio graph to be started whenever there is audio to play or record in a Room. The change is applied asynchronously on an internal queue; isEnabled reports the value you most recently set, which may not have taken effect yet.

    @brief Factory method with a block to create an instance of TVIDefaultAudioDevice.

    @discussion Use this factory method if you want to connect to a Room with your choice of audio session configuration.

 AVAudioSession *session = [AVAudioSession sharedInstance];
 NSError *error = nil;
 if (![session setCategory:AVAudioSessionCategoryPlayback
                      mode:AVAudioSessionModeVideoChat
                   options:AVAudioSessionCategoryOptionAllowBluetooth
                     error:&error]) {
     NSLog(@"AVAudioSession setCategory:options:mode:error: %@",error);
 }
